# 🔧 RT-DETR TorchScript CUDA 支持快速修复指南

## 问题总结

**问题**：导出的 TorchScript 模型无法在 Label Studio ML 后端使用 CUDA，自动切换到 CPU。

**根本原因**：TorchScript 模型在 **CPU 上 trace**，导致模型被"冻结"为 CPU 模型，即使后续加载到 CUDA 也无法运行。

## ✅ 已修复的文件

1. ✅ `rtdetrv2_pytorch/tools/export_pt.py` - 导出脚本（支持 CUDA trace）
2. ✅ `Z_export_model/快速导出模型.py` - 快速导出脚本（添加设备参数）
3. ✅ `Z_export_model/model.py` - ML 后端加载逻辑（改进 CUDA 检测）

## 🚀 立即修复步骤

### 步骤 1：重新导出模型（在 CUDA 设备上）

```bash
cd /home/ubuntu/lsn/project_new/RT-DETR-main/rtdetrv2_pytorch

python tools/export_pt.py \
    --config configs/rtdetrv2/rtdetrv2_r18vd_cancer_detection.yml \
    --resume output/rtdetrv2_r18vd_cancer_detection/best.pth \
    --mode torchscript \
    --input-size 640 \
    --device cuda \  # 关键：在CUDA上导出
    --output exported_models/rtdetr_torchscript_cuda.pt
```

**或者使用快速脚本：**

编辑 `Z_export_model/快速导出模型.py`：

```python
EXPORT_MODE = "torchscript"
EXPORT_DEVICE = None  # 自动检测CUDA
```

然后运行：

```bash
cd /home/ubuntu/lsn/project_new/RT-DETR-main/Z_export_model
python 快速导出模型.py
```

### 步骤 2：验证导出成功

导出时应该看到：

```
✅ 检测到CUDA，将在CUDA设备上导出模型（支持CUDA推理）
...
💡 模型已导出为支持 CUDA 推理的格式
```

### 步骤 3：更新 Label Studio ML 后端

1. **复制新模型到后端目录：**

```bash
cp rtdetrv2_pytorch/exported_models/rtdetr_torchscript_cuda.pt \
   /mnt/d/label-studio/rtdetr_ml_backend/models/rtdetr_torchscript.pt
```

2. **更新环境变量或 docker-compose.yml：**

```yaml
environment:
  - MODEL_PATH=/models/rtdetr_torchscript.pt
  - FORCE_CPU_INFERENCE=false  # 确保不强制CPU
```

3. **重启服务：**

```bash
docker-compose restart
```

### 步骤 4：验证 CUDA 使用

查看日志，应该看到：

```
使用 CUDA 设备: NVIDIA GeForce RTX 3090
✓ TorchScript模型加载成功（CUDA测试通过）
```

**而不是：**

```
检测到设备不一致（cuda 与 cpu），切换到 CPU 推理
```

## 📋 关键要点

1. **必须在 CUDA 上导出**：TorchScript 模型必须在目标设备（CUDA）上进行 trace
2. **自动检测**：修复后的脚本会自动检测 CUDA 并在 CUDA 上导出
3. **验证测试**：加载时会自动测试模型是否能在 CUDA 上运行

## 🔍 故障排查

### 问题 1：导出时提示 CUDA 不可用

**检查：**
```python
import torch
print(torch.cuda.is_available())  # 应该为 True
print(torch.cuda.get_device_name(0))  # 应该显示GPU名称
```

**解决：** 确保在支持 CUDA 的环境中导出

### 问题 2：导出成功但推理仍用 CPU

**检查：**
- `FORCE_CPU_INFERENCE` 环境变量是否为 `true`
- Docker 容器是否有 GPU 访问权限（`--gpus all`）
- PyTorch 是否支持 CUDA

### 问题 3：设备不一致错误

**原因：** 使用了旧的 CPU 导出的模型

**解决：** 使用修复后的脚本重新导出
