# Label Studio ML 后端训练事件配置说明

## 📋 三个训练事件的作用

### 1. `ANNOTATION_CREATED` - 标注创建事件

**触发时机：**
- 当用户在 Label Studio 中**创建新标注**并**提交**时触发
- 每次完成一个任务的标注并点击"提交"按钮时

**数据格式：**
```json
{
  "id": "任务ID",
  "task": {
    "id": "任务ID",
    "data": {
      "image": "/data/upload/xxx.jpg"
    },
    "annotations": [
      {
        "id": "标注ID",
        "result": [
          {
            "type": "rectanglelabels",
            "value": {
              "x": 10.5,
              "y": 20.3,
              "width": 30.2,
              "height": 25.1,
              "rectanglelabels": ["AD"]
            }
          }
        ]
      }
    ]
  }
}
```

**处理逻辑：**
- 从事件数据中提取标注信息
- 将标注数据保存到缓存和训练数据文件
- 如果累积的训练样本数达到阈值，自动启动训练

---

### 2. `ANNOTATION_UPDATED` - 标注更新事件

**触发时机：**
- 当用户在 Label Studio 中**修改已有标注**并**提交**时触发
- 每次编辑标注并保存时

**数据格式：**
- 与 `ANNOTATION_CREATED` 相同

**处理逻辑：**
- 与 `ANNOTATION_CREATED` 相同
- 更新缓存中的训练数据（如果该标注已存在）

---

### 3. `START_TRAINING` - 手动启动训练事件

**触发时机：**
- 在 Label Studio 界面中**手动点击"开始训练"按钮**时触发
- 通常用于强制启动训练，即使样本数未达到阈值

**数据格式：**
```json
{
  "project": {
    "id": "项目ID",
    "tasks": [...]  // 可能包含任务列表（可选）
  }
}
```

**处理逻辑：**
- **优先从缓存中获取**所有之前收集的训练数据
- 如果缓存中没有数据，尝试从项目数据中获取
- **默认行为：无论样本数多少，都会启动训练**（手动触发，用户明确要训练）
- **可选：** 设置 `ENFORCE_MIN_SAMPLES_FOR_MANUAL_TRAINING=true` 后，手动训练也需要达到最小样本数

## ⚙️ 配置方法

### 方法 1：环境变量配置（推荐）

在启动 ML 后端前设置环境变量，或在 `docker-compose.yml` 中配置：

```yaml
# docker-compose.yml
services:
  ml_backend:
    environment:
      # 训练相关配置
      - MIN_SAMPLES_FOR_TRAINING=1000      # 自动训练的最小样本数（默认1000）
      - ENFORCE_MIN_SAMPLES_FOR_MANUAL_TRAINING=false  # 手动训练是否也受最小样本数限制（默认false，不受限制）
      - TRAIN_BATCH_SIZE=8                  # 训练批次大小（默认8）
      - TRAIN_NUM_EPOCHS=10                 # 训练轮数（默认10）
      - TRAIN_LEARNING_RATE=0.0001          # 学习率（默认0.0001）
      - WAIT_FOR_TRAINING=false             # 是否等待训练完成（默认false，后台运行）
      
      # 其他配置
      - MODEL_PATH=/models/rtdetr_torchscript.pt
      - MODEL_LABELS=AD,BC,EC,L,LC,M,NT,SM,SQ,TC1,TC2,TC3
      - CONF_THRESHOLD=0.25
      - IOU_THRESHOLD=0.45
```

### 方法 2：直接修改代码

编辑 `model.py` 文件，修改默认值：

```python
# 在 fit() 方法中，约第1092行
min_samples_for_training = int(os.environ.get('MIN_SAMPLES_FOR_TRAINING', '100'))  # 改为100

# 在 _start_training_process() 方法中，约第1173-1175行
'--batch_size', os.environ.get('TRAIN_BATCH_SIZE', '4'),      # 改为4
'--num_epochs', os.environ.get('TRAIN_NUM_EPOCHS', '5'),      # 改为5
'--learning_rate', os.environ.get('TRAIN_LEARNING_RATE', '0.001'),  # 改为0.001
```

### 方法 3：修改支持的事件类型

如果需要支持其他事件类型，修改 `model.py` 第817行：

```python
# 当前支持的事件
if event not in ('ANNOTATION_CREATED', 'ANNOTATION_UPDATED', 'START_TRAINING'):
    print(f"不支持的事件类型: {event}，跳过处理")
    return

# 可以添加其他事件，例如：
# if event not in ('ANNOTATION_CREATED', 'ANNOTATION_UPDATED', 'START_TRAINING', 'ANNOTATION_DELETED'):
```

## 🔧 常用配置场景

### 场景 1：降低自动训练阈值（快速测试）

**目标：** 收集少量样本就自动开始训练

**配置：**
```bash
export MIN_SAMPLES_FOR_TRAINING=10  # 只需10个样本就训练
```

或修改代码：
```python
min_samples_for_training = int(os.environ.get('MIN_SAMPLES_FOR_TRAINING', '10'))
```

### 场景 2：禁用自动训练，只手动训练

**目标：** 只通过 `START_TRAINING` 事件手动触发训练

**配置：**
```python
# 在 fit() 方法中，修改第1114行
# 原代码：
elif len(train_data) >= min_samples_for_training:
    # 自动训练：需要达到最小样本数
    should_train = True

# 改为：注释掉或删除这个分支，只保留 START_TRAINING 的处理
```

### 场景 2.1：手动训练也受最小样本数限制

**目标：** 即使是手动触发训练，也需要达到最小样本数

**配置：**
```bash
export ENFORCE_MIN_SAMPLES_FOR_MANUAL_TRAINING=true
```

**效果：**
- 手动点击"开始训练"时，如果样本数 < MIN_SAMPLES_FOR_TRAINING，不会启动训练
- 会显示提示信息，告知样本数不足

### 场景 3：调整训练参数

**目标：** 使用更大的批次和更多轮数

**配置：**
```bash
export TRAIN_BATCH_SIZE=16
export TRAIN_NUM_EPOCHS=20
export TRAIN_LEARNING_RATE=0.0005
```

### 场景 4：等待训练完成

**目标：** 训练完成后自动更新模型

**配置：**
```bash
export WAIT_FOR_TRAINING=true
```

**注意：** 这会让 `fit()` 方法阻塞直到训练完成，可能影响响应速度。

## 📊 事件处理流程

```
用户操作
    │
    ├─> 创建标注并提交
    │       │
    │       └─> ANNOTATION_CREATED 事件
    │               │
    │               ├─> 提取标注数据
    │               ├─> 保存到缓存
    │               ├─> 检查样本数
    │               └─> 如果 >= MIN_SAMPLES_FOR_TRAINING
    │                       └─> 自动启动训练
    │
    ├─> 修改标注并提交
    │       │
    │       └─> ANNOTATION_UPDATED 事件
    │               │
    │               └─> (处理流程同上)
    │
    └─> 点击"开始训练"按钮
            │
            └─> START_TRAINING 事件
                    │
                    ├─> 从缓存获取所有训练数据
                    ├─> 无论样本数多少
                    └─> 立即启动训练
```

## ⚠️ 注意事项

1. **手动训练的行为：**
   - **默认：** `START_TRAINING` 事件不受最小样本数限制（用户明确要训练）
   - **可选：** 设置 `ENFORCE_MIN_SAMPLES_FOR_MANUAL_TRAINING=true` 后，手动训练也需要达到最小样本数
   - 这是为了避免用户误操作，在样本数不足时启动训练

2. **缓存机制：**
   - 所有标注数据都会累积在缓存中（`train_data_list`）
   - `START_TRAINING` 事件会使用缓存中的所有数据
   - 缓存不会自动清理，需要手动管理

2. **训练数据存储：**
   - 训练数据保存在 `train_data/` 目录
   - 每次事件都会创建新的 JSON 文件
   - 训练时会加载所有 JSON 文件

3. **事件触发：**
   - 只有**提交**标注才会触发事件
   - 草稿状态不会触发
   - 确保在 Label Studio 中正确提交标注

4. **训练进程：**
   - 默认在后台运行（`WAIT_FOR_TRAINING=false`）
   - 训练日志保存在 `train_logs/` 目录
   - 可以通过日志文件查看训练进度

## 📝 完整配置示例

### docker-compose.yml

```yaml
version: '3.8'

services:
  ml_backend:
    image: your-ml-backend:latest
    ports:
      - "9090:9090"
    environment:
      # 模型配置
      - MODEL_PATH=/models/rtdetr_torchscript.pt
      - MODEL_LABELS=AD,BC,EC,L,LC,M,NT,SM,SQ,TC1,TC2,TC3
      - CONF_THRESHOLD=0.25
      - IOU_THRESHOLD=0.45
      
      # 训练配置
      - MIN_SAMPLES_FOR_TRAINING=100
      - TRAIN_BATCH_SIZE=8
      - TRAIN_NUM_EPOCHS=10
      - TRAIN_LEARNING_RATE=0.0001
      - WAIT_FOR_TRAINING=false
      
      # 其他配置
      - AUTO_RELOAD_MODEL=true
      - MODEL_OUTPUT_DIR=/models
    volumes:
      - ./models:/models
      - ./train_data:/app/train_data
      - ./train_logs:/app/train_logs
```

## 🚀 快速开始

1. **设置环境变量：**
   ```bash
   export MIN_SAMPLES_FOR_TRAINING=10
   ```

2. **重启 ML 后端：**
   ```bash
   docker-compose restart ml_backend
   ```

3. **在 Label Studio 中标注：**
   - 创建标注并提交（触发 `ANNOTATION_CREATED`）
   - 或点击"开始训练"按钮（触发 `START_TRAINING`）

4. **查看日志：**
   ```bash
   docker-compose logs -f ml_backend
   ```

**提示：** 修改配置后需要重启 ML 后端服务才能生效。
